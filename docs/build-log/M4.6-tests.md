# M4.6: Test setup (Vitest + PGlite) and the first billing tests

## Goal
Real Postgres tests in memory, using the **real migrations**, with no network and no Stripe calls. These tests are what you'll show in the README and the Loom.

## Files you may touch
`package.json`, `vitest.config.ts`, `tests/helpers/db.ts`, `tests/helpers/fixtures.ts`, `tests/billing.checkout.test.ts`, `tests/access.test.ts`.

## Steps
1. `npm install -D vitest @electric-sql/pglite vite-tsconfig-paths`.
2. `vitest.config.ts`: node environment, the tsconfig paths plugin, and an alias that maps `server-only` to an empty module (it throws outside Next).
3. `tests/helpers/db.ts`: `createTestDb()` → a new `PGlite()` + `drizzle-orm/pglite` with the schema; run `migrate(db, { migrationsFolder: "drizzle" })`; seed the 3 programmes + a couple of lessons each (positions 1 and 2, lesson 1 = preview). One fresh DB per test.
4. `tests/helpers/fixtures.ts`: builders for fake Stripe objects (`checkoutSessionEvent({ mode, userId, … })`, `subscription({ id, status, priceId, … })`) and `fakeDeps({ subscriptions })`, where `retrieveSubscription` returns from the map and `now` is fixed.
5. Test through `withIdempotency` + `handleStripeEvent` exactly the way the route does:
   - **Duplicate event is a no-op:** process the same event twice → the 2nd returns `duplicate: true`; entitlement count and outbox count are unchanged.
   - **Lifetime** grants arabic + precision + usool.
   - **Arabic subscription** grants arabic + usool, not precision; `subscriptions` mirrors the status.
   - **Stale payload ignored:** the event payload says `active`, but `retrieveSubscription` returns `canceled` → the entitlement is revoked (proves D3).
   - **Unpaid checkout** (`payment_status: 'unpaid'`) → `ignored`, no entitlements.
   - **Bundle removed** when the only paid entitlement is revoked.
   - **Failed handler can retry:** a handler that throws once → the `processed_events` row is `error`; processing again succeeds and becomes `applied`.
6. `tests/access.test.ts`: preview allowed; locked denied; grace with a future `grace_until` allowed; grace with a past `grace_until` denied.
