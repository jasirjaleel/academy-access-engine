# M2.1: Clerk auth + protected routes

## Before you start (Jasir)
Create a Clerk application (email + Google sign-in). Copy `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` into `.env.local` **and** Vercel.

## Goal
Users can sign up and sign in; `/dashboard` and `/admin` require login.

## Files you may touch
`package.json`, `src/proxy.ts` **or** `src/middleware.ts` (see step 2), `src/app/layout.tsx`, `src/app/sign-in/[[...sign-in]]/page.tsx`, `src/app/sign-up/[[...sign-up]]/page.tsx`, `src/components/site-header.tsx`, `src/app/dashboard/page.tsx` (placeholder only), `src/lib/env.ts`.

## Steps
1. `npm install @clerk/nextjs`.
2. Check the installed Next.js version in `package.json`. **Next.js 16+:** the file is `src/proxy.ts`. **Next.js 15:** `src/middleware.ts`. Use `clerkMiddleware` + `createRouteMatcher(["/dashboard(.*)", "/admin(.*)"])` and call `await auth.protect()` for matching routes. Use the matcher `config` from Clerk's current docs. Webhook routes (`/api/webhooks/*`) must **not** be protected.
3. Wrap the app in `<ClerkProvider>` in `layout.tsx`.
4. Sign-in / sign-up pages using Clerk's `<SignIn />` / `<SignUp />`, centred on the page.
5. `site-header.tsx`: "Demo Academy" logo text (link to `/`), links "Pricing" and "Dashboard", then `<SignedOut>` → Sign in button, `<SignedIn>` → `<UserButton />`. Add it to the layout.
6. `dashboard/page.tsx`: a placeholder `"Assalāmu ʿalaykum, {firstName}"` using `currentUser()`. The real dashboard comes in M4.
7. In `env.ts`, move the two Clerk keys to **required**.

## ✅ Check (Jasir runs)
- Logged out, open `/dashboard` → redirected to sign-in.
- Sign up → land on the dashboard with your name.
- `npm run lint && npm run typecheck`.
