# M2.2: Sync Clerk users into the database (idempotent)

## Before you start (Jasir)
Clerk dashboard → Webhooks → add endpoint `https://<your-vercel-url>/api/webhooks/clerk`, events `user.created`, `user.updated`, `user.deleted`. Copy the signing secret → `CLERK_WEBHOOK_SIGNING_SECRET` in `.env.local` and Vercel. (Clerk can't reach localhost, so test this on Vercel.)

## Goal
The `users` table mirrors Clerk. Duplicate deliveries do nothing. A user who reaches the dashboard before the webhook arrives still gets a row.

## Files you may touch
`src/app/api/webhooks/clerk/route.ts`, `src/lib/users.ts`, `src/lib/webhooks.ts`, `src/app/dashboard/page.tsx`, `src/lib/env.ts`, `docs/DECISIONS.md` (append D8 only).

## Steps
1. `src/lib/webhooks.ts`: `withIdempotency(db, { id, provider, type }, fn)`:
   - Open a transaction and insert into `processed_events` with
     `ON CONFLICT (id) DO UPDATE SET received_at = now() WHERE processed_events.result = 'error' RETURNING id`.
     So a **new** event or a **previously failed** one proceeds, and an already-applied/ignored one returns no row.
   - No row returned → return `{ duplicate: true }` without running `fn`.
   - Otherwise run `fn(tx)` (it returns `'applied' | 'ignored'`) and set `result` to that value, inside the same transaction.
   - If `fn` throws: the transaction rolls back. Then, **outside** it, upsert the row with `result = 'error'` and a short error message (no personal data), and rethrow so the route returns 500 and the provider retries. A retry is allowed through because of the `WHERE result = 'error'` clause above.
   - **This helper is reused for Stripe in M4, so keep it generic.**
2. `src/lib/users.ts`:
   - `upsertUserFromClerk(tx, clerkUser)`: picks the **primary** email (`primary_email_address_id`) and the full name, and upserts on `id`.
   - `anonymizeUser(tx, userId)`: sets email to `deleted+{userId}@invalid`, name null, whatsapp_phone null, opt-in false. (We keep the row for billing history; see D8.)
   - `getOrCreateUser(db)`: uses `currentUser()`; if there's no row, inserts one. Returns the row.
3. Route `POST /api/webhooks/clerk`:
   - `export const runtime = "nodejs"`.
   - Read the `svix-id` header **before** verifying; it is the idempotency id (retries reuse it).
   - `verifyWebhook(req)` from `@clerk/nextjs/webhooks`; invalid → 400.
   - `withIdempotency(db, { id: svixId, provider: "clerk", type: evt.type }, ...)`. created/updated → upsert; deleted → anonymize. Other types → mark `ignored`.
   - Return 200 `{ ok: true, duplicate }`.
4. The dashboard page calls `getOrCreateUser(db)`.
5. Append to `docs/DECISIONS.md`:
   `### D8: Anonymise on user deletion` / What: on `user.deleted`, personal fields are wiped but the row stays. / Why: billing and invoice history must stay consistent, while the student's personal data is removed.
6. `env.ts`: `CLERK_WEBHOOK_SIGNING_SECRET` required.

## ✅ Check (Jasir runs, after deploying)
- Sign up with a new email → a row in `users` + a row in `processed_events` (`applied`).
- Clerk dashboard → the webhook message → **Resend** → still one user row; `processed_events` unchanged (the duplicate is ignored).
- Change your name in Clerk → the row updates.
