# M4.2: Grant access on checkout (lifetime + subscription) + bundle + outbox insert

> Use the strongest model you have. This is the core of the project.

## Goal
`checkout.session.completed` creates the correct entitlements. Subscription state is mirrored from Stripe. The free *usool* programme follows paid access. A `student.enrolled` event is written to the outbox (sending comes in M7).

## Files you may touch
`src/lib/billing/index.ts`, `src/lib/billing/checkout.ts`, `src/lib/billing/subscription-state.ts`, `src/lib/billing/bundle.ts`, `src/lib/events.ts`, `docs/DECISIONS.md` (append only).

## Steps
1. `src/lib/events.ts`, enqueue only for now:
   `enqueueEvent(tx, { type, userId, payload, dedupeKey })` inserts into `outbound_events` with `status 'pending'`, `next_attempt_at = now()`, and `ON CONFLICT (dedupe_key) DO NOTHING`. The payload holds **IDs and minimal fields only** (no email or phone).
2. `src/lib/billing/bundle.ts`, `syncBundle(tx, userId, now)`:
   - Has paid access = any entitlement with source `subscription` or `lifetime` where `status = 'active'`, or `status = 'grace' AND grace_until > now`.
   - Yes → upsert the usool entitlement (`source 'bundle'`, `source_ref 'bundle'`, `status 'active'`, clear `revoked_reason`).
   - No → if a bundle entitlement exists and isn't revoked, set `revoked`, reason `no_paid_access`.
3. `src/lib/billing/subscription-state.ts`, `applySubscriptionState(tx, sub, now)` (**M5 reuses this**):
   - `productKey = productKeyFromPriceId(sub.items.data[0].price.id)`. Unknown → throw (this is a config error and should be visible).
   - `userId = sub.metadata.userId`, otherwise look it up by `users.stripe_customer_id = sub.customer`. None → throw.
   - Upsert `subscriptions` (id, user_id, product_key, status, `current_period_end`, `cancel_at_period_end`, updated_at). Note: in recent Stripe API versions, `current_period_end` lives on `sub.items.data[0].current_period_end`. Read it from there, falling back to `sub.current_period_end` if present.
   - Entitlement for that product's programme (`source 'subscription'`, `source_ref sub.id`), status by Stripe status:
     `active | trialing` → `active` (clear grace) · `past_due` → **leave unchanged** (M5 handles it) · `canceled | unpaid | incomplete_expired` → `revoked`, reason `canceled` · `incomplete | paused` → no entitlement change.
   - Then `syncBundle`.
4. `src/lib/billing/checkout.ts`, `handleCheckoutCompleted(tx, event, deps)`:
   - `session.payment_status` must be `paid` (or `no_payment_required`); otherwise return `ignored`.
   - `userId = session.client_reference_id`; it must exist in `users`, else throw.
   - **Subscription** (`mode === 'subscription'`): `sub = await deps.retrieveSubscription(session.subscription)` (**re-fetch; never trust the payload**, see D3) → `applySubscriptionState`.
   - **Lifetime** (`mode === 'payment'`): derive `productKey` from `session.metadata.productKey`, **and** verify it equals `lifetime`. `source_ref = session.payment_intent` (string ID). Upsert the `arabic` + `precision` entitlements (`source 'lifetime'`, `active`) → `syncBundle`.
   - `enqueueEvent(tx, { type: 'student.enrolled', userId, payload: { productKey }, dedupeKey: \`enrolled:${userId}:${productKey}\` })`.
   - Return `applied`.
5. Wire `checkout.session.completed` and `customer.subscription.updated` (→ re-fetch by `event.data.object.id`, then `applySubscriptionState`) into `handleStripeEvent`.
6. Append to `DECISIONS.md`: `D9: Product is derived from the price ID, not trusted from metadata` (metadata is set by our own server, but the price ID is what Stripe actually charged).
