# M4.1: Stripe webhook route (signature + idempotency + dispatch)

> Use the strongest model you have for M4.1 and M4.2.

## Before you start (Jasir)
Run `stripe listen --forward-to localhost:3000/api/webhooks/stripe` and copy the `whsec_…` it prints into `.env.local` as `STRIPE_WEBHOOK_SECRET`. (The Vercel endpoint gets its own secret later.)

## Goal
A thin, safe webhook route. It verifies the signature, wraps the event in `withIdempotency` (built in M2.2), and hands it to a dispatcher. Unknown events are recorded as `ignored`.

## Files you may touch
`src/app/api/webhooks/stripe/route.ts`, `src/lib/billing/index.ts`, `src/lib/billing/types.ts`, `src/lib/env.ts`.

## Steps
1. `src/lib/billing/types.ts`:
   ```ts
   export type BillingDeps = {
     retrieveSubscription: (id: string) => Promise<Stripe.Subscription>;
     now: () => Date;
   };
   export type HandlerResult = "applied" | "ignored";
   ```
   Handlers receive `(tx, event, deps)`. **No handler may import the `stripe` client directly.** That keeps them testable in M4.6.
2. `src/lib/billing/index.ts`: `handleStripeEvent(tx, event, deps): Promise<HandlerResult>`, a `switch` on `event.type`. For now every case returns `"ignored"`; M4.2 fills in `checkout.session.completed`. Also export `liveDeps` built from the real `stripe` client.
3. Route `POST /api/webhooks/stripe`:
   - `export const runtime = "nodejs"`; `export const dynamic = "force-dynamic"`.
   - `const body = await req.text()` (the **raw** body, never `req.json()`), header `stripe-signature`.
   - `stripe.webhooks.constructEvent(body, sig, env.STRIPE_WEBHOOK_SECRET)`; failure → 400 `{ error: "invalid signature" }`, logging nothing but the message.
   - `withIdempotency(db, { id: event.id, provider: "stripe", type: event.type }, (tx) => handleStripeEvent(tx, event, liveDeps))`.
   - Return 200 `{ received: true, duplicate }`. Any thrown error → 500 (Stripe retries).
   - Log only `event.id` and `event.type`.
4. `env.ts`: `STRIPE_WEBHOOK_SECRET` required.
