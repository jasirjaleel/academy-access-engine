# M4.3: Access rules (server-side only)

## Goal
One module decides who can watch what, and the lesson route uses it. A locked lesson must **never** send its `video_url` to the browser.

## Files you may touch
`src/lib/access.ts`, `src/app/dashboard/lessons/[id]/page.tsx` (minimal version; M4.5 builds the full UI), `src/components/locked-lesson.tsx`.

## Steps
1. `src/lib/access.ts` (`import "server-only"`; every function takes `(db, …, now = new Date())`):
   - `isEntitlementLive(e, now)`: `status === 'active' || (status === 'grace' && grace_until > now)`.
   - `getProgrammeAccess(db, userId, now)` → `Record<slug, { hasAccess: boolean; status: 'active' | 'grace' | 'none'; graceUntil: Date | null; sources: string[] }>` for all 3 programmes.
   - `canWatchLesson(db, userId, lessonId, now)` → `{ allowed: boolean; reason: 'preview' | 'entitled' | 'locked'; lesson; programme }`.
2. Minimal lesson page: a server component. `auth()` → `canWatchLesson`.
   - Allowed → render the title (EN + AR) and a `<video controls src={lesson.video_url}>`.
   - Locked → render `<LockedLesson programme={…} />`: the title, a short message, and a button to `/pricing`. **Don't pass `video_url` to any client component or prop on this path.**
   - Unknown lesson ID → `notFound()`.
